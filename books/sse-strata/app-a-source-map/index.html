A.6 怎么自己重新锚定（别信任何行号，包括本书的）

# 1) 先看文件是否变了（mtime 是 UTC，+8 才是北京时间）
stat -c '%n %s bytes mtime=%y' SSEStraBed/src/program/generate.cpp Strata/serve/server.py rag-proxy/rag_proxy.py

# 2) 用"标识符 + 语义"锚定，而不是用行号
grep -n 'int prompt_cache = ' SSEStraBed/src/program/generate.cpp
grep -n 'def prepare' Strata/serve/server.py
grep -n 'def overfit_error' rag-proxy/rag_proxy.py

# 3) 需要看上下文时按行区间读，读前确认区间真的是那段代码
sed -n '2594,2612p' Strata/serve/server.py

三条纪律（来自 18 章与 memory annotation-anchor-verification）：

  1. 标识符存在 ≠ 代码结构存在 —— 相似度重新锚定不可信，落地前必须备份 + 严格 diff + 编译；
  2. 绝对路径先 ls/realpath（事故 4）；
  3. 两个仓库同名文件行号不同（A.0），引用时永远写全路径。

A.7 本附录小结

  • 引擎只有一个入口：src/program/generate.cpp（8091 行）——CLI、serve 主循环、批槽、降级全在里面；
    想改 prefill / 批槽 / 观测，先从这里找到调用点，再进 src/prefill/、src/spec/、src/core/。
  • 服务层只有一份 Python（Strata/serve/server.py + frontend.py），两条 lane 共用 ——
    这就是"事故 3 修一处覆盖两通道"的原因，也是它的坑：改完必须重启两条 lane 才都生效（B 到 10-19 18:58 才跟上）。
  • 网关的锚点集中在计数与改写（text_tokens_upper / count_tokens / overfit_error / 窗口预检），
    10-19 的事故与修复全在这一块。
  • 压测台与取证工具是独立目录（~/bench、Strata/tools、~/tools），不在引擎仓库里 ——
    别在 SSEStraBed/ 里找压测脚本。
  • 本附录所有行号 核实于 2026-10-20 02:00 北京；文件一改就漂。用 A.6 的方式重新锚定，别复制粘贴行号。
