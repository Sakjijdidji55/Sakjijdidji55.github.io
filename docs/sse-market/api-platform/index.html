10 API 平台：兼容与计费

4 分钟读完 · 1,522 字

ai-infra 的统一出口：对外提供 OpenAI 兼容接口（另有 Claude 协议适配），对内转发到 vLLM 等上游，按 token 计费并按 Key 限流。

仓库：github.com/SysuMirror/sseapi（TypeScript，server/ 约 8700 行、web/ 约 5400 行、docs/）。

账号与密钥

① 集市 OAuth 登录

  • 用户操作：用集市账号登录控制台。
  • 实现：授权码换 token → 取 userinfo → 建本地会话；控制台与 API 用两套凭证，互不复用。
GET  /api/auth/oauth/config     返回 client_id 等公开参数
GET  /api/auth/oauth/login-url  生成授权地址
POST /api/auth/oauth/token      code 换令牌
GET  /api/auth/oauth/userinfo   取用户信息
GET  /api/auth/me               当前登录用户

② 创建 API Key

  • 用户操作：控制台创建 Key → 可选绑定域名 → 复制 sk- 开头的串 → 填进客户端。
  • 实现：Key 只展示一次，库中存哈希；可绑定来源域名，泄露后非白名单来源无法使用。
GET    /api/keys
POST   /api/keys
PATCH  /api/keys/:id
DELETE /api/keys/:id
  • 坑：Key 与用户是多对一，计费与限流都挂在 Key 上。若挂在用户上，一个人给三个项目建的 Key 会互相抢配额。

③ 余额与流水

  • 用户操作：看余额、看每条调用扣了多少、看充值记录。
  • 实现：balance 当前余额、ledger 流水明细、summary 汇总；每次调用写一条用量记录并带余额快照。
GET /api/billing/balance
GET /api/billing/ledger
GET /api/billing/summary
  • 面试点：流水必须存「本笔之后的余额」。只存变动额，对账时要重放全部历史才能算出某一时点余额。

④ 每日签到

  • 用户操作：控制台点签到，领取小额额度。
  • 实现：签到按「用户 + 日期」唯一，重复签到返回已签；奖励直接入账并写流水。
GET  /api/billing/checkin
POST /api/billing/checkin
  • 坑：日期要用服务端时区统一计算。用客户端时区，「跨时区重复签到」就成立。

模型目录

① 注册模型

  • 用户操作：管理员登记模型（上游地址、模型名、单价、限流）。
  • 实现：上游地址 + served_model_name + 上游 Key + 入出单价 + RPM/并发；对外只暴露平台的 Slug，/v1/models 返回的是 Slug 列表。
GET    /api/models
POST   /api/models
GET    /api/models/:modelId
DELETE /api/models/:id
  • 坑：served_model_name 必须与上游 vLLM 的启动参数一致。不一致时上游返回 model not found，而网关常把它包装成 502，排查时容易误判为网络问题。

② 协议连通性测试

  • 实现：test 发一次最小请求验证可用；test-protocol 单独验证协议兼容性（流式字段、usage 字段是否存在），不与业务请求混在一起。
POST /api/models/test
POST /api/models/:id/test
POST /api/models/:id/test-protocol
  • 坑：健康检查要区分「连通」与「协议兼容」。只 ping 通的上游，可能在流式响应里缺 usage，导致计费全靠估算。

请求转发

① 统一入口

POST /v1/chat/completions     OpenAI 兼容对话（支持流式）
POST /v1/embeddings           向量化
POST /v1/rerank               重排
POST /v1/images/generations   文生图
POST /v1/messages             Claude 协议（经适配层转换）
  • 实现：所有入口共用一套前置流程 —— 用 Bearer sk- 找 Key → 校验状态与余额 → 校验来源 → 按 Slug 找上游 → 转发 → 旁路计费。

② Claude 协议适配

  • 实现：claude-adapter.ts 把 Anthropic 风格的 messages 请求与响应双向转换，客户端可以继续用 Claude SDK，上游仍是 OpenAI 兼容服务。
// server/src/services/claude-adapter.ts —— 请求/响应字段映射与流式事件转换
  • 坑：协议转换要处理「系统提示」与「工具调用」的字段差异。只转文本字段，工具调用会在适配层丢失。

③ 用量提取

  • 实现：流式响应里逐行解析 data:，取最后一条带 usage 的事件；非流式直接读响应体 usage。两者都拿不到时按字符数估算（约 4 字符 1 token），并标记为估算值。
// server/src/routes/proxy.ts
function extractUsageFromSse(buf: string): {
  prompt: number; completion: number; cached: number; imageTokens: number; found: boolean
} {
  let last = { prompt: 0, completion: 0, cached: 0, imageTokens: 0, found: false };
  for (const line of buf.split(/\r?\n/)) {
    const t = line.trim();
    if (!t.startsWith('data:')) continue;
    const data = t.slice(5).trim();
    if (!data || data === '[DONE]') continue;
    try {
      const j = JSON.parse(data);
      const u = readUsage(j?.usage);
      if (u.found) last = u;      // 取最后一条带 usage 的
    } catch {
      /* 忽略半包 */
    }
  }
  return last;
}

function estimateTokens(messages: unknown, completionText: string) {
  const msgLen = JSON.stringify(redactImagesForEstimate(messages) ?? '').length;
  return {
    prompt: Math.max(1, Math.ceil(msgLen / 4)),
    completion: Math.max(0, Math.ceil((completionText || '').length / 4)),
    cached: 0,
    imageTokens: 0,
  };
}
  • 坑：SSE 分块会切断 JSON。解析失败要跳过；抛错的话，一个半包就让整次调用失败。
  • 坑：估算前要把图片内容替换掉（redactImagesForEstimate）。base64 图片的字符数会把 token 估到几十万。
  • 面试点：估算值要落库标记来源（usage_source = usage | estimate）。把估算当真实用量计费，账单一定会被质疑。

计费与限流

① 计费口径

  • 实现：单价按「每百万 token」存，输入与输出分别计价，可另设缓存价与图片价；扣费后写流水与余额快照。
cost = prompt_tokens / 1e6 * input_price_per_1m
     + completion_tokens / 1e6 * output_price_per_1m
  • 坑：金额用整数分或定点数累加。用浮点会累积误差，对账时总是差几分钱，且无法回溯是哪一笔。

② 限流

  • 实现：RPM 与并发两档限制，维度是 Key；超限返回 429 并给出重试时间。
GET /api/admin/rate-limits
GET /api/admin/rate-limits/status
  • 面试点：RPM 与并发是两种约束。只限 RPM，突发并发仍能打满上游；只限并发，慢速高频请求仍能把连接数占满。

③ 余额不足

  • 实现：请求前置检查余额，不足直接拒绝，不转发到上游；已发生的调用照常扣费。

  • 坑：余额检查要在转发之前。放到响应之后，欠费用户可以无限调用直到下次登录。

来源校验

① 域名白名单

  • 实现：Key 可绑定来源列表；匹配时把输入归一化成 host 再比较，允许配置裸域名或完整 URL。
// server/src/services/origins.ts
export function parseOriginList(raw: string | undefined | null): string[] {
  if (!raw) return [];
  return String(raw).split(/[\n,;]+/).map((s) => s.trim()).filter(Boolean);
}

function normalizeHost(input: string): string {
  let s = input.trim().toLowerCase();
  if (!s) return '';
  try {
    if (s.includes('://')) return new URL(s).host;
  } catch { /* ignore */ }
  ...
}
  • 坑：比较必须用归一化后的 host（小写、去端口、去协议）。直接字符串比较会因大小写或尾部斜杠误判。

② 密钥存储

  • 实现：Key 与用户 Token 都只存哈希；列表接口只返回前缀与末四位，用于识别。

  • 坑：返回完整 Key 的「查看」功能不存在。需要重新获取只能新建并废弃旧的。

管理与观测

① 用户与额度

  • 实现：管理员可查用户、改额度、看单人用量与请求明细。
GET   /api/admin/users
PATCH /api/admin/users/:id
GET   /api/admin/usage/by-user
GET   /api/admin/usage/by-user/:userId/reqs

② 调用日志

  • 实现：每次调用记 Key、Slug、token 数、耗时、状态码；可按时间与 Key 过滤。
GET /api/admin/logs
GET /api/admin/stats
  • 坑：日志里不能记请求正文。对话内容可能含隐私与密钥，排障只需要元数据。

③ 文档

  • 实现：/api/docs 提供接口元数据，docs/ 目录存放接入文档；控制台按模型生成调用示例。
GET /api/docs
GET /api/public/docs

API 平台 · 面试速答

  • 兼容层：对外 OpenAI 兼容，另有 Claude 协议适配；model 字段是平台 Slug，换上游不动客户端。
  • 转发：统一前置（Key → 余额 → 来源 → 上游），流式原样透传并旁路计费。
  • 用量：优先取上游 usage，取不到按 4 字符 1 token 估算并标记来源。
  • 计费：按每百万 token，整数分累加，流水带余额快照。
  • 限流：RPM 与并发双约束，维度为 Key。
  • 安全：Key 只存哈希、可绑来源 host 白名单（归一化后比较）。
