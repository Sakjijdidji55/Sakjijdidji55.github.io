12 全平台面试速答

1 分钟读完 · 500 字

前面各章是按平台讲的，这一章按问题讲：面试里最常被连问的五组问题，每组给一句结论加一句依据。

架构与边界

  • 一套账号，N 个系统：UniSSO 是唯一身份源，主站是 OAuth IdP，各平台独立库。
  • 跨平台写数据只有两种方式：验签接口（SM2）或带短期票据的 API，绝不共享数据库连接。
  • 凭证一律不落前端：access_token 只存服务端（图床），主站 token 不注入 WebView（App）。

一致性与缓存

  • 列表缓存换代：generation 版本号，写入即换，O(1) 失效。
  • 详情缓存：所有写路径主动失效，容易漏，要收敛到少数几个入口。
  • 计数类（浏览数）：Redis 为准 + 脏标记批量回写，绝不 UPDATE num = num + 1。
  • 唯一索引兜底：投币上限、抽奖去重、签到去重，都靠数据库约束，不靠代码判断。

并发与异步

  • goroutine 必须脱离请求 ctx（context.Background()），否则请求返回就取消。
  • 异步任务三件套：超时、去重、失败不无限重试。
  • 切场景要清理旧状态（ZREM 旧 key、删未读索引），否则数据虚高。

安全

  • 状态码即信息：404 不泄露存在性，401/403/422/429 各有含义。
  • 签名要带时间窗 + nonce：否则可重放。
  • 生物特征不可撤销：人脸只做二次验证，不做主登录。
  • 慢哈希给密码，快哈希给 Token：用户密码用 bcrypt，高熵 Token 用 SHA-256。
  • 平台只存公钥：SM2 模块鉴权，私钥给模块方，平台不持有。

时间与状态

  • 封禁用时间戳不用布尔值：到期自动恢复，不依赖定时任务。
  • 开奖/发放要幂等：状态字段做条件更新，任务重跑不出错。
  • 递补按「通过时间」排，不按报名时间。

代码均取自各仓库，为便于阅读做了删减与示意化处理；版本迭代后以仓库为准。
