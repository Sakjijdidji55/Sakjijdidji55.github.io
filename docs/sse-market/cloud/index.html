03 集市云：一组一容器

9 分钟读完 · 3,944 字

自助算力平台：一个组（group）对应 K3s 命名空间 clouds 里的一个 Pod，用户拿到 root，可在其中部署服务、申请数据库与对象存储、绑定子域名。平台自身是 Flask + gunicorn（单 worker，SocketIO 需要粘性会话）+ React SPA。

仓库：github.com/SysuMirror/yatterra（Python，web/ 后端 + web/frontend/ 前端 + manifests/ + systemd/）。

组容器

① 创建组

  • 用户操作：填组名 → 选规格（CPU / 内存 / 存储 / GPU 卡数）→ 选类型（Linux / Windows / Android）→ 选节点（默认 auto）→ 创建。
  • 实现：
    1. 组名先规范化为小写 RFC1123 名称（[a-z0-9-]，字母数字开头结尾），否则 kubectl apply 会拒绝并留下孤儿 manifest 与 home 目录。
    2. 规格缺省按类型补齐：GPU 组、Windows 组、Android 组各有一套默认 CPU / 内存。
    3. 节点选择：auto 表示不写 placement 字段；Windows / Android 组强制 auto，因为 /dev/kvm 与 VM 磁盘只在默认节点上。
    4. 组定义写入 groups.json（状态文件），再渲染 Deployment 并 apply。
  • 关键代码
# web/groups.py
def create_group(name, gpus=None, cpu=None, mem=None, storage=None, creator=None,

  • 面试点：状态文件 groups.json 是权威来源，K3s 只承载运行态。这样即使集群被清空，按状态文件可以重建全部组。

② 规格：limits 与 requests 分离

  • 用户操作：创建时填的 CPU / 内存是上限，实际占用通常低于上限。
  • 实现：Deployment 里 limits 用用户填的值，requests 用 EWMA 估算值。二者分离，调度器按真实用量算账，用户仍可短时突发到上限。

# web/req_estimate.py
def request_for(g):
    """Return (cpu_req_str, mem_req_str, storage_req_str) for deployment_yaml.

    Computes the request from the accumulated EWMA at pod-creation time.
    With no history, falls back to min(limit, limit × DEFAULT_REQ_FRACTION).
    """
    limit_cpu = parse_cpu(g.get("cpu", "1"))
    limit_mem = parse_mem_gi(g.get("mem", "1Gi"))
    limit_storage = parse_storage_gi(g.get("storage", "1Gi"))
    st = load_state()
    e = st.get(g.get("name", "")) or {}
    # storage 由 hostPath 提供，不计入 Kubernetes 的 ephemeral-storage 预留
    storage_req = fmt_storage_gi(min(limit_storage, FLOOR_STORAGE_GI))
    if e.get("cpu_ewma") is None or e.get("samples", 0) < 3:
        # 样本不足：取「上限 × DEFAULT_REQ_FRACTION」，并设下限
        cpu_req = fmt_cpu(min(limit_cpu, max(FLOOR_CPU, limit_cpu * DEFAULT_REQ_FRACTION)))
        mem_req = fmt_mem_gi(min(limit_mem, max(FLOOR_MEM_GI, limit_mem * DEFAULT_REQ_FRACTION)))
        return cpu_req, mem_req, storage_req
    eff_cpu, eff_mem = eff_cpu_mem(e)          # 有效用量取 EWMA 与 p90 的较大者
    cpu_req = fmt_cpu(_target_cpu(eff_cpu, limit_cpu))
    mem_req = fmt_mem_gi(_target_mem_gi(eff_mem, limit_mem))
  • 坑：requests 只在 Pod 重建时计算，运行期不热改。否则每次采样都会触发滚动更新，容器被反复重启。
  • 坑：hostPath 的字节数不能当 requests 用。Kubernetes 不把它算进 ephemeral-storage，写进去会让调度器误判。
  • 面试点：requests 决定调度与驱逐优先级，limits 决定 cgroup 上限。把两者设成相等会让节点利用率长期停在低水位。

④ 迁移节点、扩缩容、改名、重置密码

  • 用户操作：组设置里改规格、指定新节点迁移、改组名、重置容器密码。
  • 实现：迁移是先在新节点渲染并 apply，等新 Pod 就绪后再删旧的；改名要同步重写 frpc 与 nginx 托管块；重置密码改的是 Deployment 的 CLOUD_PASSWORD 环境变量并触发滚动更新。

⑥ 日志与在线终端

  • 用户操作：查看容器日志、应用日志，打开 Web 终端执行命令。
  • 实现：日志与终端都通过 kubectl logs -f / exec 转 WebSocket 流，前端按行渲染。
# web/api/pods.py —— 日志以 SSE 流式返回
def stream_logs(name):
    pod = deploys.resolve_pod(name)
    if not pod:
        return jsonify({"error": "Pod 未运行"}), 404

    def _stream():
        args = ["kubectl", "-n", groups.NS, "logs", "-f", "--tail=100", pod]
        yield from _iter_log_process(args)

    resp = Response(_stream(), mimetype="text/event-stream")
    resp.headers["Cache-Control"] = "no-cache"
    resp.headers["X-Accel-Buffering"] = "no"   # 关掉 nginx 缓冲，否则日志被攒住
  • 坑：流式连接要设空闲超时并支持客户端断开时释放 exec 进程，否则每次断线都会在 Pod 里残留一个 shell。

⑦ 端口代理

  • 用户操作：临时访问组内某个端口（如 8080 的开发服务），不绑定子域名。
  • 实现：平台按 pod + port 反代到集群内的 Service，路径带随机前缀，会话结束即失效。

部署

① 从 Git 部署

  • 用户操作：填仓库地址与分支 → 选组 → 选启动方式（自动识别或自定义脚本）→ 部署。
  • 实现：
    1. validate_repo 校验地址形态，只接受 http(s) / git 协议。
    2. 组内浅克隆代码到工作目录。
    3. 按 deploy.sh 或自动识别（Python / Node / Go）生成启动命令。
    4. 注册到 supervisord，崩溃自启、开机自启。
    5. 运行记录写入部署表，状态与日志可回看。
# web/deploys.py
def run(group, dep, wait=False, skip_if_same_ref=False):
    """Clone/pull, (re)write program conf, (re)start via supervisorctl.

    wait / skip_if_same_ref 供 push-to-deploy 使用：
      wait=True            同一记录已有部署在跑就排队等待
      skip_if_same_ref=True  ref 未变化且程序 RUNNING 时跳过重启（重投幂等）
    """
    fd, got = _deploy_lock(group, dep["id"], wait=wait)
    if not got:
        msg = "已有部署正在进行中，本次未执行（请稍后重试）"
        audit.record("deploy_run",
                     detail="%s/%s id=%s skipped=locked" % (group, dep.get("name"), dep["id"]),
                     module="deploys")
        return False, msg
  • 坑：克隆必须限定深度。全量克隆大仓库会把构建超时耗尽在下载阶段。

② 自定义脚本的路径校验

  • 用户操作：填一个 deploy.sh 的绝对路径，平台执行它。
  • 实现：路径必须绝对、不含 ..、且只允许 /home/cloud/ 或 /shared/ 前缀。这三条挡住了「写 /etc/cron.d/x 让平台以 root 执行」的路径。
# web/deploys.py
def validate_script(path):
    """Validate a local deploy.sh path inside the pod. Returns (ok, msg)."""
    p = (path or "").strip()
    if not p:
        return False, "脚本路径不能为空"
    if not p.startswith("/"):
        return False, "脚本路径必须是绝对路径"
    if ".." in p.split("/"):
        return False, "路径不能含 .."
    if not any(p.startswith(pre) for pre in _SCRIPT_PREFIXES):
        return False, "脚本路径仅允许 /home/cloud/ 或 /shared/ 下"
    return True, ""
  • 面试点：这类「让用户指定可执行文件」的接口，校验点落在路径白名单上；按文件名或后缀校验挡不住 .. 和软链。

③ Webhook 自动部署

  • 用户操作：在仓库里配一个 Webhook，push 后自动部署。
  • 实现：两种密钥作用域。全局密钥可以触发任意「仓库 + 分支」匹配的部署；单部署密钥只能触发它自己那条记录，泄露后影响面被限定。
# web/deploys.py
def match_webhook(source, headers, body, repo_url, branch):
    """Authorize a push for (repo_url, branch). Returns (matched, mode).

    mode: "per_deploy" (某条部署自己的密钥签了 body),
          "global"     (全局密钥签名 → 所有匹配 repo/branch 的记录),
          None         (未通过)
    """
    cands = find_by_repo_branch(repo_url, branch)
    matched = [(g, d) for (g, d) in cands if verify_for_deploy(source, headers, body, d)]
  • 坑：验签必须对原始 body 做，不能在 JSON 解析再序列化之后做。字段顺序变化会导致签名永远对不上。
  • 面试点：密钥作用域从「全局」细化到「单条部署」，是把爆炸半径写进设计里。

④ 部署队列与 GPU 部署

  • 用户操作：提交部署后显示排队位次；GPU 组里可同时跑多个小任务。

网络与存储

① 子域名映射

  • 用户操作：填子域名 + 容器端口 → 保存 → 一分钟内可公网访问。
  • 实现：一条映射要过五道校验 —— 子域正则（1–63 位小写字母数字连字符）、保留名黑名单、端口范围、端口黑名单（集群内部服务端口）、唯一性（子域不重复、端口不重复、不与现有 nginx server_name 冲突）。
# web/proxy_map.py
def add(subdomain, port, note="", pod=None):
    sub = (subdomain or "").strip().lower()
    if not SUB_RE.match(sub):
        return False, "子域只允许小写字母数字和连字符,1-63 字符"
    if sub in RESERVED:
        return False, f"子域 {sub} 是保留名,禁止"
    port = int(port)
    if not (1 <= port <= 65535):
        return False, "端口范围 1-65535"
    if port in BLOCKED_PORTS:
        return False, f"端口 {port} 是集群内部服务端口,禁止映射到公网"
    state = _load()
    if any(m["subdomain"] == sub for m in state):
        return False, f"子域 {sub} 已存在"
    if any(m["port"] == port for m in state):
        return False, f"端口 {port} 已被其他映射占用"
    if _conf_has_servername(sub):
        return False, f"nginx 里段外已有 {sub}.{DOMAIN} 的 server_name,请先手工清理"
    rec = {"id": sub, "subdomain": sub, "port": port, "enabled": True, "pod": pod,
           "note": (note or "").strip()[:120]}
    state.append(rec)
    _save(state)
    ok, msg = apply()          # 重写 frpc 与 nginx 托管块
  • 坑：端口黑名单是最容易被忽略的一道。放通 kubelet 或内部 API 端口，等于从公网直接打控制面。

② frp 隧道与 nginx 托管块

  • 实现：Pod 只监听内网端口，公网流量经 frpc → frps → 本机 nginx。frpc 配置与 nginx 站点都由代码生成，且用标记块包起来，重写时整块替换。
# web/groups.py
def frpc_segment(name, local_port, remote_port):
    return f"""[[proxies]]
name = "{name}"
type = "tcp"
localIP = "127.0.0.1"
localPort = {local_port}
remotePort = {remote_port}
"""

def build_managed_block(state):
    lines = [FRPC_MARK_BEGIN]
    lines.append(frpc_segment("platform-gui", 8090, PLATFORM_GUI_PORT - 10000))
    for g in state["groups"].values():
        lines.append(frpc_segment(f"grp-{g['name']}-ssh", g["ssh_nodeport"], g["ssh_public"]))
        lines.append(frpc_segment(f"grp-{g['name']}-web", g["web_nodeport"], g["web_public"] - 10000))
    lines.append(FRPC_MARK_END)

def valley_windows(result, frac=0.33, max_windows=3):
    """Contiguous low-p50 windows (p50 <= min + frac*(max-min)), longest first."""
    slots = (result or {}).get("slots") or []

        return []
    p50 = [s["p50"] for s in slots]

  • 组与 Pod：一组一 Pod（namespace clouds），状态在 groups.json，K3s 只承载运行态。

  • 网络：frpc 隧道 + 本机 nginx，配置由代码生成并用标记块整块重写，天然幂等。
  • GPU：NVIDIA_VISIBLE_DEVICES 做可见性隔离，MPS 百分比做算力切分，调度器分训练/服务两套放置规则。
  • 治理：压力驱逐带滞回恢复；巡检与告警单点失败不影响主循环；计量异常间隔退回固定间隔。
  • 计费：金额用整数分；每个资源键独立四舍五入，总额等于各键之和。
  • 幂等：钱包转账靠共享 token 唯一约束，支付回调靠 out_trade_no 查重。
  • AI：工具调用按调用者权限判定；RAG 的权限过滤在召回阶段完成。
