09 开发者平台：权限、部署与小程序

6 分钟读完 · 2,440 字

生态的「应用市场 + 权限中心 + 部署台 + 小程序宿主」，三者后续合并为同一个开发者平台。

合并说明：本文按合并后的结构组织 —— 8.1–8.4 是开发者平台本体（模块、密钥、SM2 总线、权限），8.5–8.8 是部署台（已并入），8.9 是小程序（占位，合并完成后补写）。三个仓库当前仍是独立进程，合并期间通过 SM2 验签与短期票据互通。

仓库：github.com/SysuMirror/developer（模块与总线，约 9000 行 TypeScript）、github.com/SysuMirror/deploy（部署台，apps/deploy-api 约 1.9 万行 + apps/deploy-web）、github.com/SysuMirror/applet（小程序宿主，约 6000 行 Node.js）。

登录与开发者身份

① 集市 OAuth 登录

  • 用户操作：用集市账号登录 → 首次进入自动建本地用户。
  • 实现：授权码换令牌 → 取 userinfo → 按 sub upsert 本地用户；令牌只用于本次换身份，不落库。
GET  /oauth/start      → 跳转集市授权
GET  /oauth/callback   → code 换 token → 取 userinfo → 建会话

② 开发者申请

  • 用户操作：非开发者提交申请（用途、预期模块）→ 管理员审批 → 通过后获得开发者身份。
  • 实现：审批通过时同时置 is_developer 并映射到内置 developer 角色，历史数据无需手工迁移。
POST /api/applications        提交申请
GET  /api/admin/applications  待审列表
POST /api/admin/applications/:id/review
  • 坑：审批状态与角色授予要在同一事务内完成。只改申请状态不授角色，用户会看到「已通过」却仍然不能建模块。

③ 花名与资料

  • 实现：花名只用于展示，不参与任何权限判断；留空即回退实名。

模块与密钥

① 注册模块

  • 用户操作：填名称、slug、说明 → 提交 → 拿到一对 SM2 密钥（私钥只显示一次）。
  • 实现：slug 全局唯一，作为总线里的模块标识；注册时生成密钥对，平台只保存公钥。

② 只存公钥

常规做法：平台存密钥，模块带密钥调用  → 平台被拖库 = 所有模块可被伪造
这里的做法：平台只存公钥，私钥给模块 → 平台被拖库也伪造不了任何模块请求
  • 面试点：SM2 是非对称的，验签只需要公钥。平台不需要知道私钥，因此就不该持有 —— 这是把「最小权限」落到密钥管理上。

③ 密钥轮换

  • 实现：轮换时新私钥一次性下发，旧公钥保留一段灰度期，期间新旧两把公钥都接受验签。

  • 坑：轮换不能「立即废弃旧公钥」。模块方滚动发布需要时间，立刻废弃会让灰度中的实例全部鉴权失败。

SM2 签名总线

① 请求格式

POST /api/open/modules/ping
x-model-Authorization: base64url(slug).base64url(ts).base64url(nonce).base64url(sign)
x-model-query-time: 1730000000000
  • 签名串（四段，\n 连接）：
slug\nts\nnonce\nqueryTime

// server/src/middleware/module-auth.ts
const raw = String(req.headers[MODEL_AUTH_HEADER] || '').trim();
const queryTime = String(req.headers[QUERY_TIME_HEADER] || '').trim();
const v = verifyModelToken(raw, queryTime);   // 四段拆解 + SM2withSM3 验签
if (!v.ok) return res.status(401).json({ code: 401, message: v.error });

② 三重时间校验

校验项 容差 拦截目标
ts（签名内） ±5 分钟 重放数天前的旧请求
queryTime（独立头） ±60 秒 短窗口内的缓存重放
nonce 5 分钟去重缓存 同窗口内重复提交

③ nonce 去重

  • 实现：内存 Map 记录已用 nonce，写入前惰性清理过期项，不额外起定时器。
const nonceSeen = new Map<string, number>();
for (const [k, t] of nonceSeen) {
  if (t < cutoff) nonceSeen.delete(k);
}
if (nonceSeen.has(nonceKey)) {
  return res.status(401).json({ code: 401, message: 'nonce 已使用，疑似重放' });
}
nonceSeen.set(nonceKey, Date.now());
  • 坑：Map 在进程内。多实例部署时各算各的，挡不住跨实例重放，需要换 Redis。
  • 面试点：queryTime 独立于签名，是为了让网关单独做时效判断，因此容差可以比 ts 更严（±60 秒 vs ±5 分钟）。

④ 出站调用

  • 实现：模块反向调平台（发布工作台入口、读模块 API）时，同样带 SM2 签名；平台侧用模块公钥验签，不依赖共享密钥。
POST /api/open/workbench/publish   模块 → 平台：注册工作台入口
GET  /api/open/modules/:slug/apis  平台 → 模块：拉模块自述的接口清单

权限模型

① 权限点目录

// server/src/services/permissions.ts
export const PERMISSION_CATALOG: PermissionDef[] = [
  // developer.*  6 项：模块管理、密钥、文档、入口…
  // admin.*      9 项：用户、审批、角色、授权…
];
  • 实现：权限点集中在目录里声明，角色与直授都引用目录中的 code；新增能力只加一条，不改判定逻辑。

② 角色与直授

最终权限 = 角色权限（可挂多角色，取并集）
         ± 直授（对单用户 allow / deny，deny 优先）
  • 面试点：deny 优先于 allow，是权限系统的安全默认值。allow 是「补一点」，deny 是「紧急刹车」，刹车必须优先。

③ 模块级可见性

  • 实现：模块声明 required_permission；无权限时列表里不出现，直接访问详情返回 404。
列表：过滤掉无权限的模块（过滤掉，不做置灰）
详情：404 —— 不暴露「这个模块存在」
  • 面试点：403 适合「你知道有这个资源但不能动」，404 适合「连存在性都不该知道」。模块市场属于后者。

④ 管理台

  • 实现：用户管理、开发者审批、平台入口增删改、模块管理、角色 CRUD、挂角色、直授/拒权、模块 API 授权审批、文档外链；每个操作对应一个 admin.* 权限点。

  • 坑：管理台最容易漏的是「前端隐藏 + 后端不校验」。每个按钮背后都要有接口级判断。

部署台：项目与成员

① 项目

  • 用户操作：developer 角色自助建项目 → 填名称、说明 → 自动成为 owner。
  • 实现：项目表 + 成员表；一人可加入多个项目，成员带资源角色。
GET    /api/projects
POST   /api/projects
GET    /api/projects/:id
DELETE /api/projects/:id
GET    /api/projects/:id/members
POST   /api/projects/:id/members
DELETE /api/projects/:id/members/:userId

② 资源角色与模块范围

  • 实现：项目内分 owner / maintainer / member；成员还可被授予「可见模块范围」（moduleScope），只能看到范围内的模块。
// apps/deploy-api/src/services/project.ts
export function getProjectRole(...)          // 取当前用户在该项目的角色
export function canWriteProject(...)         // 写权限判定
export function canReadProject(...)          // 读权限判定
export function isProjectOwner(...)
export function setProjectMemberScope(...)   // 设置可见模块范围
export function addModuleMember(...)         // 模块级成员
  • 坑：模块范围的判定要覆盖「列表、详情、部署、日志」四条路径。只过滤列表，直接构造 URL 仍能访问详情。

③ 审批单表

  • 实现：所有审批进单表 applications，用 type 区分业务；admin 发起免审并记 auto_approved_by_role。
applications(id, type, applicant_id, target_id, payload, status, approver_id, created_at)
  • 面试点：审批中心是统一入口，待办需要跨类型查询；按业务分表会让「我的待办」变成多表 UNION。

④ 审计

  • 实现：状态变更写 audit_logs；部署台另有访问日志查询（access-log-query.ts）供排障。
GET /api/audit-logs
GET /api/projects/:id/logs

部署台：部署流程

① 队列与并发

  • 用户操作：点「部署」→ 排队 → 看到实时日志 → 完成。
  • 实现：单进程队列 + 并发上限；同一 module:env 同时只允许一个部署在跑，其余排队等待。
// apps/deploy-api/src/services/deploy-worker.ts
export function enqueueDeployment(deploymentId: string) {
  if (running.has(deploymentId) || queue.includes(deploymentId)) return;  // 去重
  queue.push(deploymentId);
  pump();
}

function pump() {
  while (running.size < MAX_CONCURRENT) {
    const idx = queue.findIndex((id) => {
      const dep = getDeployment(id);
      if (!dep) return true;                    // 无效记录，丢弃
      const key = `${dep.moduleId}:${dep.env}`;
      return !activeModuleEnv.has(key);         // 同模块同环境串行
    });
    if (idx === -1) break;
    const id = queue.splice(idx, 1)[0];
    const dep = getDeployment(id);
    if (!dep) continue;
    start(id, `${dep.moduleId}:${dep.env}`);
  }
}
  • 面试点：并发按「模块 + 环境」串行。全局串行会让所有人的部署互相阻塞；完全并发又会同时改同一套容器。
  • 坑：enqueueDeployment 必须做入队去重。用户连点两次会产生两条相同部署，第二条必然失败。

② 取消与恢复

  • 实现：cancelDeployment 通过 AbortController 中断子进程；recoverStaleDeployments 在服务启动时把「卡在 running 但没有进程」的记录标为失败。
export function cancelDeployment(...)         // 中断执行
export function getDeploymentLogs(...)        // 拉日志
export function recoverStaleDeployments(...)  // 启动时清理僵尸记录
  • 坑：进程被 kill 时 running 集合是内存态，重启后全丢。没有 stale 恢复，数据库里会永久留着「部署中」的记录。

③ 灰度发布

  • 用户操作：正式域名上带一个灰度 Header 即可访问测试版本，不带则走正式版本。
  • 实现：nginx 按 Header 值路由；灰度值在配置里维护，生成正则时逐项转义。
// apps/deploy-api/src/config/gray.ts
export function grayValuesNginxRegex(): string {
  return grayConfig.headerValues.map((v) => escapeRegex(v)).join('|');
}

function escapeRegex(s: string): string {
  return s.replace(/[.*+?^${}()|[\]\\]/g, '\\$&');
}

export function getGrayReleaseInfo(moduleName: string, prodUrl: string) {
  const { headerName, recommendedValue, headerValues, versionHeaderName } = grayConfig;
  return { headerName, headerValue: recommendedValue, headerValues, versionHeaderName,
    description: `在正式域名上携带灰度 Header 将路由到测试容器，否则走正式版本` };
}
  • 坑：Header 值拼进 nginx 正则前必须转义。值里出现 . 或 | 会改变匹配语义，灰度范围直接失控。

④ 域名绑定

  • 实现：项目维度管理域名，绑定后由部署流程写入反代配置。
GET    /api/projects/:id/domains
POST   /api/projects/:id/domains
DELETE /api/projects/:id/domains/:domainId
  • 坑：删除域名要先摘反代配置再删记录。顺序反了会出现「记录没了、配置还在」，请求继续打到旧容器。

⑤ 环境与配置

  • 实现：env-config 按环境存变量；preview 提供预览地址；runs 记录每次执行。
GET /api/projects/:id/env-config
GET /api/projects/:id/preview
GET /api/projects/:id/runs

部署台：脚本应用与存储

① 脚本应用

  • 用户操作：建一个「脚本应用」→ 填根目录与命令 → 成员可手动触发。
  • 实现：根目录必须是绝对路径且落在允许范围内（allowedRoots）；命令拼接用 shellQuote 逐段转义。
// apps/deploy-api/src/services/script-apps.ts
export function validateWorkdir(workdir: string): string {
  const dir = (workdir ?? '').trim();
  if (!dir) throw new ScriptError('请填写根目录（执行命令时先 cd 到这里）');
  if (!dir.startsWith('/')) throw new ScriptError('根目录必须是绝对路径');
  const normalized = normalizePath(dir);
  const roots = allowedRoots();
  const ok = roots.some((r) => normalized === r || normalized.startsWith(`${r}/`));
  if (!ok) throw new ScriptError(`根目录必须位于允许范围内：${roots.join('、')}`);
  return normalized;
}

/** 纯字符串规范化（不触碰文件系统，避免路径不存在时误判） */
function normalizePath(p: string): string { ... }
  • 坑：normalizePath 必须是纯字符串处理，不能用 fs.realpath。路径不存在时 realpath 抛错，会把「合法但尚未创建」的目录判为非法。
  • 面试点：允许范围用「等于根 或 以 根/ 开头」两个条件。只判前缀，/data-evil 会被 /data 放行。

② 对象存储

  • 实现：按模块建 MinIO 桶，凭证按模块签发；支持把历史数据同步进桶，并查看同步进度。
export function resolveModuleMinioCreds(...)
export function ensureModuleBucket(...)
export function syncHistoryDataToBucket(...)
export function getObjectStorageStatus(...)
export function listModuleBucketObjects(...)

GET  /api/projects/:id/object-storage
GET  /api/projects/:id/object-storage/credentials
GET  /api/projects/:id/object-storage/objects
GET  /api/projects/:id/object-storage/sync
GET  /api/projects/:id/object-storage/sync/:jobId
  • 坑：同步任务要能续跑。一次几万条记录的同步中断后从头开始，既慢又会产生重复对象。

③ 数据导出

  • 实现：项目数据可导出为 zip（含清单），导出前做权限校验。
GET /api/projects/:id/data-export
GET /api/projects/:id/data-export.zip

平台联动

① 工作台入口发布

  • 实现：模块通过 SM2 签名调主站的内部接口，把入口注册到工作台；主站验签后落库，不需要开发者平台直接写主站库。
// server/src/routes/workbench-publish.ts —— 模块 → 平台 → 主站（SM2 验签中转）

② 开放 API 清单

  • 实现：模块自述接口（/api/open/modules/:slug/apis），平台汇总后在文档页展示，并作为授权审批的粒度（整组或单点 group.action）。
GET /api/apis
GET /api/api-detail
GET /api/modules
  • 面试点：授权粒度到「接口」；整模块授权在模块变多后必然过度授权。

小程序（占位）

  • 现状：小程序目前是独立服务（applet.ssemarket.cn），提供目录、版本审核、启动票据、设备订阅；代码在 github.com/SysuMirror/applet。三者合并完成后，本节补写完整实现；当前只保留接口契约与迁移要点。
  • 迁移计划：并入开发者平台，作为其中一个模块；届时启动会话、签名验签、目录管理的能力收敛到本平台的权限与审批模型之下。
  • 迁移期间仍需保持的接口契约（App 侧依赖）：
POST /v1/launch-tickets       申请一次性票据（60s）
POST /v1/sessions/exchange    票据换 mp_session Cookie
GET  /v1/sessions/me          当前会话
GET  /v1/apps                 小程序目录
  • 坑：票据只能消费一次，兑换必须用 Redis GETDEL 或数据库条件更新；迁移时若更换会话存储，mp_session 的名称、作用域与 HttpOnly 属性要保持不变，否则已登录的小程序会全部掉线。

开发者平台 · 面试速答

  • 密钥：平台只存 SM2 公钥，私钥一次性下发；轮换保留旧公钥灰度期。
  • 签名：四段 token（slug / ts / nonce / queryTime），三重时间校验（±5 分钟、±60 秒、nonce 5 分钟去重）。
  • 权限：权限点目录 + 角色并集 + 直授，deny 优先；模块无权限时列表不出现、详情 404。
  • 部署队列：并发上限 + 同 module:env 串行 + 入队去重 + 启动时清理僵尸记录。
  • 灰度：nginx 按 Header 路由，配置值拼正则前必须转义。
  • 脚本应用：根目录白名单（等于根或以 根/ 开头），路径规范化用纯字符串。
  • 存储：按模块建桶与凭证，同步任务可续跑。
