07 App：六平台与九种产物

5 分钟读完 · 2,252 字

Flutter 多端客户端：一套 Dart 代码出 Android / iOS / HarmonyOS / 桌面 / Web，作为主站的移动入口，同时充当小程序宿主。lib/ 约 4 万行、124 个 dart 文件。

仓库：github.com/SysuMirror/SSEMarket-X。关键依赖：webview_flutter 4.6、web_socket_channel、flutter_local_notifications 19、just_audio 0.9、shared_preferences。

多端形态

① 支持矩阵

六个原生平台加一个 Web 端，共九种产物（Android 三种 ABI 各算一种）：

平台 产物 说明
Android arm64-v8a / armeabi-v7a / x86_64 按 CPU 架构分包，2015 年前的老设备走 v7a
iOS nosign 未签名包，需自行签名或开发者账号安装
HarmonyOS nosign 未签名包，需自行签名安装
Windows x64 / arm64 ARM 笔记本（如骁龙本）单独出包
macOS universal Intel 与 Apple 芯片共用
Linux x64 主流发行版
Web — 能力受限：无本地通知，小程序走外部窗口 
android/  ios/  ohos/  linux/  macos/  windows/  web/     ← 七套宿主工程
lib/core/        api / models / router / services / miniprogram / skins
lib/views/       auth / home / post / chat / notice / coin / shop / miniprogram / profile / xiaoqiu / todo
lib/shared/      components / theme
  • 实现：lib/ 被七套宿主工程共用，业务代码只写一遍；平台差异集中在 core/services 与 core/miniprogram，用 Platform.is* 与 MethodChannel 分流。

② 平台能力差异

能力 实现方式 差异
本地通知 Android / iOS / macOS / Windows / Linux 用 flutter_local_notifications HarmonyOS 走原生 MethodChannel('ssemarket/notifications')；Web 不支持，降级为空操作
小程序容器 移动端内嵌 WebView，桌面端开外部窗口 Web 与桌面无内嵌 WebView
后台保活 Android 生命周期通道 start / stop 其他平台不做保活
音频 just_audio macOS 有独立分支处理 
// lib/core/services/notification_service.dart
/// - Android / iOS / macOS / Windows / Linux 走 flutter_local_notifications；
/// - HarmonyOS 走原生 MethodChannel（ssemarket/notifications），
///   在 ohos/entry/src/main/ets/entryability/EntryAbility.ets 中实现。
/// - Web 不支持，全部降级为空操作。
  • 坑：把「平台不支持」写成抛异常，会让 Web 端每个页面都报错。正确做法是降级为空操作，业务侧只判断「有没有触发」。

③ HarmonyOS 的依赖覆盖

  • 实现：OHOS 使用 OpenHarmony TPC 的 Flutter 分支，依赖覆盖写在单独的 pubspec_overrides.ohos.yaml；构建其他平台时不带这个文件。
pubspec.yaml                  公共依赖
pubspec_overrides.ohos.yaml   仅在构建 OHOS 时生效的 dependency_overrides
  • 坑：覆盖文件常驻会让 Android/iOS 构建去拉 OHOS 分支的包，编译直接失败。构建脚本要按目标平台增删该文件。

④ 桌面端：开外部窗口

  • 实现：Windows 上按固定候选路径找 Edge / Chrome / Brave，用 --new-window --app=<url> 以「应用窗口」模式启动（无地址栏）；找不到浏览器才退回系统默认打开。macOS / Linux / Web 直接 launchUrl 外部打开。
Future<void> _openDesktopWindow(Uri uri) async {
  if (kIsWeb) {
    await launchUrl(uri, mode: LaunchMode.externalApplication);
    return;
  }
  final url = uri.toString();
  if (Platform.isWindows) {
    final pf = Platform.environment['ProgramFiles'] ?? r'C://Program Files';
    final pf86 = Platform.environment['ProgramFiles(x86)'] ?? r'C://Program Files (x86)';
    final local = Platform.environment['LOCALAPPDATA'] ?? '';
    final candidates = <String>[
      '$pf86\\Microsoft\\Edge\\Application\\msedge.exe',
      '$pf\\Microsoft\\Edge\\Application\\msedge.exe',
      '$pf\\Google\\Chrome\\Application\\chrome.exe',
      '$pf\\BraveSoftware\\Brave-Browser\\Application\\brave.exe',
    ];
    for (final path in candidates) {
      if (File(path).existsSync()) {
        await Process.start(path, <String>['--new-window', '--app=$url'],
            mode: ProcessStartMode.detached);
        return;
      }
    }
  }
  await launchUrl(uri, mode: LaunchMode.externalApplication);
}
  • 坑：桌面端不能在主窗口叠加载入遮罩。开窗是外部进程完成的，遮罩等不到回调，界面会一直转圈。
  • 面试点：--app= 让浏览器以无地址栏的应用窗口打开，看起来像独立客户端；代价是依赖用户装了 Chromium 系浏览器。

⑤ 移动端：内嵌 + 保活

  • 实现：移动端用内嵌 WebView；Android 额外通过生命周期通道开启保活，让小程序音频在切后台后继续播放。
Future<void> _setKeepAlive(bool on) async {
  if (on == _keepAliveStarted) return;
  _keepAliveStarted = on;
  if (!Platform.isAndroid) return;       // 只有 Android 做保活
  await _lifecycle.invokeMethod<bool>(on ? 'start' : 'stop');
}
  • 坑：保活必须与「离开容器」成对调用。只 start 不 stop，退出小程序后前台服务还在，通知栏会一直挂着。

网络与身份

① API 封装

  • 实现：ApiService 用常量 base 地址，一个业务动作一个方法，统一解析响应体里的 code / msg / data，错误以异常向上抛。
// lib/core/api/api_service.dart
static const String _baseUrl = 'https://ssemarket.cn/api';
static const String webBaseUrl = 'https://ssemarket.cn';

final uri = Uri.parse('$_baseUrl/auth/login');
...
final uri = Uri.parse('$_baseUrl/auth/showDetails');
  • 坑：base 地址写死会让测试环境与灰度无法切换。要么走构建变量注入，要么把 host 收进配置类。

② 令牌存储

  • 实现：StorageService 用 shared_preferences 存三个键 —— 访问令牌、刷新令牌、刷新令牌到期时间；启动时读回并恢复登录态。
// lib/core/services/storage_service.dart
static const String _keyToken = 'user_token';
static const String _keyRefreshToken = 'refresh_token';
static const String _keyRefreshTokenExpiry = 'refresh_token_expiry';

final token = _prefs.getString(_keyToken) ?? '';
if (token.isNotEmpty && userJson != null) {
  _token = token;
}
  • 坑：shared_preferences 在 Android 是明文 XML、iOS 是明文 plist，root/越狱设备可直接读。需要更强保护时接 flutter_secure_storage（Keychain / Keystore）。

③ 令牌刷新

  • 实现：登录响应同时返回 access 与 refresh；refresh_token_expiry 决定何时不再尝试刷新，直接跳登录。
// 登录返回
final refreshToken = data['refresh_token'] is String ? data['refresh_token'] as String : '';
return LoginResult(token: token, refreshToken: refreshToken);
  • 坑：刷新失败要一次性清理三个键并回登录页。只清 access 不清 refresh，下次启动会拿过期 refresh 反复请求，形成死循环。

主站功能

① 首页与搜索

  • 实现：views/home/home_page.dart 承载分区与信息流，search_page.dart 做帖子/用户搜索，均走 ApiService 的浏览接口。
final uri = Uri.parse('$_baseUrl/auth/browse');

② 帖子详情

  • 用户操作：看正文、图片、LaTeX 公式、点赞、收藏、投币、评论、分享。
  • 实现：post_detail_page.dart（1400+ 行）+ latex_markdown.dart（1200+ 行）自绘 Markdown 与公式；表情选择器 emoji_picker.dart 独立组件。
lib/views/post/post_detail_page.dart   详情、评论、点赞、收藏
lib/shared/components/markdown/latex_markdown.dart   Markdown + LaTeX 渲染
lib/shared/components/inputs/emoji_picker.dart       表情输入
  • 坑：LaTeX 与 Markdown 混排必须同一次解析完成。先渲染 Markdown 再替换公式，会把公式里的 _、* 当成斜体/加粗吃掉。

③ 发帖

  • 实现：create_post_page.dart 支持标题、正文、图片、匿名、分区；图片先上传拿地址再拼进正文。

④ 私信

  • 实现：websocket_service.dart 维持长连接，views/chat 渲染会话；断线重连后按最后消息 ID 补拉历史。

  • 坑：移动端切后台会断连。回到前台要先补拉历史再重连，否则中间的消息在界面上是空洞。

⑤ 通知

  • 实现：notification_service.dart 申请权限、处理点击跳转、显示新帖通知；notice_service.dart 拉站内通知与未读数。
init()                 初始化通道与点击回调
requestPermission()    申请通知权限
showNewPosts()         新帖提醒
openSystemSettings()   权限被拒后引导到系统设置
  • 坑：点击通知的跳转要在 App 冷启动时就绪。只在热启动注册回调，冷启动点通知会落在首页，到不了目标页。

⑥ 在线心跳

  • 实现：模块级单例，登录后每 60 秒上报一次；页面用 setTarget 切换「正在看什么」，切场景立即补一次；切后台暂停。
// lib/core/services/presence_service.dart
static const Duration _defaultInterval = Duration(seconds: 60);

void start(ApiService api) {
  _api = api;
  if (!StorageService().isLoggedIn) return;
  if (_timer != null) return;
  _active = true;
  unawaited(beat());
  _timer = Timer.periodic(_defaultInterval, (_) => unawaited(beat()));
}

void setTarget(String scene, {int targetID = 0}) {
  _scene = scene;
  _targetID = scene == 'home' ? 0 : targetID;
  if (_active) unawaited(beat());   // 切场景立即补一次
}

Future<void> beat() async {
  if (_inFlight || !_active) return;   // 防重入：上一发没回来就跳过
  ...
}
  • 坑：_inFlight 这个标志不能省。弱网下请求悬挂，定时器每 60 秒再发一次，会堆出一串并发请求。

⑦ 投币与打分

  • 实现：views/coin 是投币弹窗与流水；views/todo/score_page.dart 是打分专区入口（目录名 todo 是历史命名，内容是打分）。

小程序容器

① 目录与票据预取

  • 实现：mini_program_catalog.dart 拉目录并缓存；prefetchTickets 提前申请票据放进本地缓存，点开时直接取，减少等待。
// mini_program_runtime.dart
Future<void> open(MPApp app) async {
  ...
  final ticket = await _takeTicket(app);   // 先用预取缓存，没有再实时申请
  ...
}
  • 坑：预取的票据有 60 秒 TTL。缓存必须带过期判断，过期就重新申请，不能直接复用。

② 申请票据

  • 实现：mp_platform_api.dart 调 POST /v1/launch-tickets，带上 appKey、deviceID、可选 origin。
Future<MPLaunchTicket> launchTicket({required String appKey, String? origin}) async {
  final data = await _request('POST', '/v1/launch-tickets', body: {
    'appKey': appKey,
    'deviceID': await deviceId,
    if (origin != null && origin.isNotEmpty) 'origin': origin,
  });
  return MPLaunchTicket(
    ticket: data['ticket']?.toString() ?? '',
    launchUrl: data['launchURL']?.toString() ?? '',
    expiresIn: (data['expiresIn'] as num?)?.toInt() ?? 60,
    app: data['app'] == null ? null : MPApp.fromDynamic(data['app']),
  );
}

③ 来源校验

  • 实现：打开前用 _isAllowed(app, uri) 比对应用配置的 origin 白名单；不匹配直接拒绝，不进入 WebView。
if (!_isAllowed(effectiveApp, uri)) { /* 拒绝打开 */ }
  • 坑：来源校验必须比对「解析后的 origin」，不能对 URL 做字符串前缀匹配。https://evil.com/?x=applet.ssemarket.cn 在前缀匹配下会被放行。

④ 内部应用的令牌注入

  • 实现：只为自家托管的小程序注入主站访问令牌 —— 条件是 https + 主机 applet.ssemarket.cn + 路径以 /mp/ 开头；注入方式是在页面里设置 window.__SSE_MAIN_TOKEN__ 并广播事件。
// lib/core/miniprogram/mini_program_runtime.dart
bool _isInternalMpUrl(String url) {
  final uri = Uri.tryParse(url);
  if (uri == null) return false;
  return uri.scheme == 'https' &&
      uri.host == 'applet.ssemarket.cn' &&
      uri.path.startsWith('/mp/');
}

Future<void> _injectMainToken(String url) async {
  if (!_isInternalMpUrl(url)) return;      // 第三方应用不注入
  final controller = _controller;
  if (controller == null) return;
  final token = StorageService().token;
  if (token.isEmpty) return;
  final encoded = jsonEncode(token);
  final script = '''
(function(){
  try {
    var t = $encoded;
    window.__SSE_MAIN_TOKEN__ = t;
    if (typeof window.__setSSEAppToken === 'function') window.__setSSEAppToken(t);
    window.dispatchEvent(new Event('sse-main-token'));
  } catch(e) {}
})();
''';
  await controller.runJavaScript(script);
}
  • 面试点：注入对象是短期 access token：它只读业务接口、几小时过期。refresh token 能换新令牌，泄露等同于账号被接管，不下发给 WebView。
  • 坑：注入脚本要 try/catch 包住。目标页若 CSP 禁止内联脚本，runJavaScript 会抛异常，不捕获会中断整个打开流程。

⑤ 桥接与返回

  • 实现：_onBridgeMessage 处理小程序发来的消息（关闭、跳转、标题变更）；handleBack 先给 WebView 一次返回机会，再退出容器；pauseMedia 在小程序切走时暂停音频。
_onBridgeMessage   容器与页面的消息通道
handleBack         返回键优先给页面，其次退出
pauseMedia         离开时停音频
_setKeepAlive      常驻标记
  • 坑：返回键必须让页面先处理。直接退出容器，用户会以为「按返回就把小程序关了」，实际只是回到了上一页。

⑥ 设备注册与订阅

  • 实现：mp_platform_api.dart 的 registerDevice / updateSubscriptions 把 deviceID 与订阅关系上报平台，推送由平台按订阅下发。
Future<void> registerDevice(...)
Future<void> updateSubscriptions(...)

音乐播放

① 播放器

  • 实现：music_player_service.dart 基于 just_audio，暴露 play / pause / toggle / stop；播放状态通过 ValueNotifier 通知界面。
void play(...) / pause() / toggle() / stop() / dispose()
  • 坑：dispose 必须释放底层播放器实例。只置空引用，音频焦点不会归还，其他应用的声音会被压低。

② 帖子内嵌音乐

  • 实现：正文里的 ::music <id>:: 在客户端被解析成卡片，点击后交给播放器；播放与页面解绑，离开详情页仍继续。

本地能力

① 缓存管理

  • 实现：media_cache_service.dart 管理图片/音频缓存，cache_management_page.dart 展示占用并可清理。

  • 坑：缓存要设上限与 LRU 淘汰。只增不减，长期使用后占用会到 GB 级，用户只能卸载重装。

② 浏览历史与稍后再看

  • 实现：browse_history_service.dart 与 watch_later_service.dart 本地存储 + 服务端同步；browse_history_page.dart 提供列表与清理。

③ 皮肤与桌面布局偏好

  • 实现：skins/ 定义主题，desktop_layout_preference_service.dart 记住桌面端的窗口/侧栏布局。

App · 面试速答

  • 多端：六平台 + Web，九种产物（Android 三种 ABI）；七套宿主工程共用 lib/，平台差异收敛在 core/services 与 core/miniprogram。
  • OHOS：独立 pubspec_overrides.ohos.yaml，构建其他平台必须移除；通知走原生 MethodChannel。
  • 平台差异：桌面用 --app= 开浏览器应用窗口、移动内嵌 WebView；桌面不能叠加载遮罩；保活只在 Android。
  • 身份：shared_preferences 存 access / refresh / expiry 三键；更严场景需 Keychain / Keystore。
  • 心跳：60 秒单例心跳，切场景立即补报，_inFlight 防重入。
  • 小程序：预取票据（60s TTL）→ 来源白名单校验 → 仅自家 /mp/ 页面注入 access token。
  • 坑位：返回键先给页面、通知冷启动要注册回调、缓存要 LRU、播放器要 dispose。
