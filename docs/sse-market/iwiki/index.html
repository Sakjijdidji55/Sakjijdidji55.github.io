04 iWiki：协作、检索与开放

9 分钟读完 · 3,748 字

企业知识库：空间 → 页面树 → 页面正文，支持两种协作模式（Yjs 实时协同 / 普通文档三路合并）、版本快照链、按权限过滤的 RAG 问答、仓库转文档（CodeWiki），并对外提供 MCP 服务。

仓库：github.com/SysuMirror/iwiki。Monorepo：apps/iwiki-api（Express + SQLite）、apps/iwiki-web（Vue 3）、apps/iwiki-mcp（MCP 服务）、packages/sse-ui（设计系统）。后端约 3.7 万行 TypeScript。

空间与页面

① 个人空间与共享空间

  • 用户操作：注册后自动拥有个人空间；可建团队共享空间，也可把空间挂到其他空间下形成多级知识库。
  • 实现：spaces 表带 parent_id 与 owner_id；个人空间按用户 ID 派生固定 ID（personalSpaceId(userId)），发布共享的源只能是自己的个人空间。
  • 关键代码
// src/services/page-publish.ts —— 只有「个人空间 → 共享空间」这一条发布路径
export function publishPageToSpace(
  pageId: string, userId: string, targetSpaceId: string,

  if (!row) throw new Error('文档不存在');

  const sourceRow = getSpaceRow(page.spaceId);

  const sourceSpace = mapSpace(sourceRow);
  if (page.spaceId !== personalSpaceId(userId)) { /* 拒绝：源必须是本人个人空间 */ }
  ...
}
  • 面试点：发布时改写同一条 pages 记录的 space_id 并调整可见性，不复制数据，因此发布后旧链接仍然有效。

② 目录树与移动

  • 用户操作：新建、重命名、拖拽移动、删除页面；目录实时刷新。
  • 实现：pages.parent_id 自引用建树，ON DELETE SET NULL 保证删父节点不会级联删子节点（子节点上提为根）；idx_pages_space 支撑按空间过滤。
  • 关键代码
-- src/db/init.ts
CREATE TABLE IF NOT EXISTS pages (
  id TEXT PRIMARY KEY,
  space_id TEXT NOT NULL REFERENCES spaces(id) ON DELETE CASCADE,
  parent_id TEXT REFERENCES pages(id) ON DELETE SET NULL,
  title TEXT NOT NULL,
  content TEXT NOT NULL DEFAULT '',
  visibility TEXT NOT NULL DEFAULT 'public',
  editor_id TEXT NOT NULL REFERENCES users(id),
  view_count INTEGER NOT NULL DEFAULT 0,
  updated_at TEXT NOT NULL,
  allow_all_edit INTEGER NOT NULL DEFAULT 0,
  published INTEGER NOT NULL DEFAULT 1
);
CREATE INDEX IF NOT EXISTS idx_pages_space ON pages(space_id);
  • 坑：ON DELETE SET NULL 与 ON DELETE CASCADE 的选择决定了删除语义。目录里删父节点，子节点应当上提，所以这里用 SET NULL。
  • 实现补充：移动后调用 invalidateCatalogAfterMove 让目录缓存失效，避免把旧树结构继续发给前端。

③ 创建页面

  • 用户操作：在空间里点「新建」，填标题后进入编辑器。
  • 实现：校验空间存在 → 校验有权在该空间建页 → 父页面必须属于同一空间且可见 → 落库并返回页面对象。
// src/services/page-create.ts
export function createPageRecord(input: CreatePageInput): Page {
  const spaceId = input.spaceId?.trim();
  const title = input.title?.trim();
  if (!spaceId || !title) pageCreateError('缺少 spaceId 或 title', 400);

  const spaceRow = getSpaceRow(spaceId);
  if (!spaceRow) pageCreateError('空间不存在', 404);
  const space = mapSpace(spaceRow);
  if (!canCreateInSpace(space, input.actorUserId, input.actorUserRole)) {
    pageCreateError('无权在该空间创建文档', 403);
  }

  const parentId = input.parentId ?? null;
  if (parentId) {
    const parentRow = db.prepare('SELECT * FROM pages WHERE id = ?').get(parentId);
    if (!parentRow || parentRow.space_id !== spaceId || !canViewPage(...)) {
      /* 父页面不属于该空间或不可见 → 拒绝，避免构造出跨空间挂载 */
    }
  }
  ...
}
  • 坑：父页面必须校验「同空间」。只校验存在性，可以让 A 空间的页面挂到 B 空间的树下，目录渲染时越权泄露标题。

④ 空间级联删除

  • 用户操作：删除空间（需管理员权限），其下所有子空间与页面一并清除。
  • 实现：先收集子树空间 ID 与页面 ID，再在一个事务里删 RAG 分块、删页面、删挂在空间上的收集记录，最后删空间。
// src/services/space-tree.ts
export function deleteSpaceCascade(spaceId: string): { spaceIds: string[]; pageIds: string[] } {
  const spaceIds = collectSpaceSubtreeIds(spaceId);
  const pageIds = collectSpacePageIds(spaceIds);
  assertManagedPagesCanPurge(pageIds);
  assertManagedSpacesCanPurge(spaceIds);
  const placeholders = spaceIds.map(() => '?').join(',');
  const tx = db.transaction(() => {
    for (const pageId of pageIds) deletePageRagChunks(pageId);
    if (pageIds.length) {
      const ph = pageIds.map(() => '?').join(',');
      db.prepare(`DELETE FROM pages WHERE id IN (${ph})`).run(...pageIds);
    }
    // 收集空间被删时，挂在它上面的收集记录一并清理（外键约束 + 避免空壳）
    db.prepare(`DELETE FROM assignment_collections WHERE collection_space_id IN (${placeholders})`).run(...);
  });
  tx();
  ...
}
  • 坑：向量分块必须显式删除。SQLite 表有外键级联，向量索引表没有，漏删会留下「搜得到但打不开」的孤儿向量。
  • 面试点：级联删除用「收集 ID → 单事务删除」；数据库级联覆盖不到向量库与文件存储，因为它们不在同一个事务域内。

编辑、版本与冲突

① 两种协作模式

  • 用户操作：无感知。新文档默认实时协同；把文档切为「普通文档」后变为单人编辑 + 保存时合并。
  • 实现：pages.collab_mode 两个取值 —— collab（Yjs 实时协同，最后发布者为准）与 normal（单人编辑，保存时三路合并）。
-- src/db/init.ts —— 迁移时补列，默认 'collab'
ALTER TABLE pages ADD COLUMN collab_mode TEXT NOT NULL DEFAULT 'collab';
  • 面试点：两种模式并存是按文档类型分工 —— 长文档、多人同时改的场景用 CRDT；表格/PPT 这类结构化内容用单人编辑 + 合并，避免 CRDT 处理结构化属性的复杂度。

② 本地草稿与云草稿

  • 用户操作：编辑时自动保存；关掉浏览器再打开，草稿还在；换设备也能接上。
  • 实现：本地草稿（浏览器）+ 云草稿 page_drafts，主键是 (page_id, user_id)，同一用户对同一页只保留一份。
CREATE TABLE IF NOT EXISTS page_drafts (
  page_id TEXT NOT NULL REFERENCES pages(id) ON DELETE CASCADE,
  user_id TEXT NOT NULL REFERENCES users(id),
  title TEXT NOT NULL,
  content TEXT NOT NULL DEFAULT '',
  visibility TEXT NOT NULL DEFAULT 'public',
  allowed_user_ids TEXT NOT NULL DEFAULT '[]',
  updated_at TEXT NOT NULL,
  PRIMARY KEY (page_id, user_id)
);
  • 坑：云草稿按「页面 + 用户」存，不按「页面」存。否则两人同时编辑会互相覆盖草稿。

③ 版本链：快照 + 反向 diff

  • 用户操作：看历史版本、对比、回滚。
  • 实现：wiki_revision 每版存一条，is_snapshot 标记全量快照，其余存 reverse_diff（反向差分，从后一版回退到这一版）；expire_mark 供清理任务识别可回收版本。
-- src/db/init.ts
CREATE TABLE IF NOT EXISTS wiki_revision (
  rev_id INTEGER PRIMARY KEY AUTOINCREMENT,
  page_id TEXT NOT NULL REFERENCES pages(id) ON DELETE CASCADE,
  rev_no INTEGER NOT NULL,
  editor_uid TEXT NOT NULL,
  is_snapshot INTEGER NOT NULL DEFAULT 0,
  full_content BLOB NULL,
  reverse_diff BLOB NULL,
  config_snapshot TEXT NULL,   -- 结构化页面（表格/流程图/PPT/画布）的配置，与正文同版本
  create_ts INTEGER NOT NULL,
  expire_mark INTEGER NOT NULL DEFAULT 0,
  UNIQUE(page_id, rev_no)
);
CREATE INDEX IF NOT EXISTS idx_rev_page_no ON wiki_revision(page_id, rev_no);
CREATE INDEX IF NOT EXISTS idx_rev_expire ON wiki_revision(expire_mark);
  • 坑：存「反向 diff」：回滚的频率远低于前进，反向 diff 让「从最新版回退到任意历史版」变成顺序重放，不必先重建全量再算差。
  • 面试点：config_snapshot 与正文同版本落库。表格、PPT 的正文只是占位，真正的数据在配置里；只存正文会导致回滚后格式全丢。

④ 三路合并（normal 模式）

  • 用户操作：两人改同一篇普通文档，后保存的人看到冲突标记，逐块选择。
  • 实现：node-diff3 的 diff3Merge(ours, base, theirs)；无冲突区块直接拼接，冲突区块包成 Git 风格标记并记录行号区间。
// src/services/collab/merge-service.ts
/** 三路合并：base=打开时基线, ours=用户草稿, theirs=线上最新 */
export function threeWayMerge(base: string, ours: string, theirs: string): MergeResult {
  const chunks = diff3Merge(splitLines(ours), splitLines(base), splitLines(theirs));
  const mergedLines: string[] = [];
  const conflictList: ConflictItem[] = [];
  let lineNo = 1;

  for (const chunk of chunks) {
    if ('ok' in chunk && chunk.ok) {
      mergedLines.push(...chunk.ok);
      lineNo += chunk.ok.length;
      continue;
    }
    if ('conflict' in chunk && chunk.conflict) {
      const { a, b } = chunk.conflict;
      const startLine = lineNo;
      mergedLines.push(CONFLICT_START);
      mergedLines.push(...a);
      mergedLines.push(CONFLICT_SEP);
      mergedLines.push(...b);
      mergedLines.push(CONFLICT_END);
      const blockLen = 1 + a.length + 1 + b.length + 1;
      conflictList.push({ startLine, endLine: startLine + blockLen - 1, oursContent: [...a], theirsContent: [...b] });
      lineNo += blockLen;
    }
  }
  return { hasConflict: conflictList.length > 0, mergedText: joinLines(mergedLines), conflictList };
}
  • 坑：合并必须按行切。按字符切会让中文段落的冲突区间错位，前端无法定位到具体块。
  • 面试点：hasConflictMarkers 单独导出，用于判断「用户手改的正文里是否残留冲突标记」，防止把 <<<<<<< 直接发布出去。

⑤ 编辑锁

  • 用户操作：普通文档被他人编辑时，会提示「XX 正在编辑」。
  • 实现：wiki_edit_lock 以 page_id 唯一，记录持有者与过期时间；拿不到锁则进入只读。
CREATE TABLE IF NOT EXISTS wiki_edit_lock (
  lock_id INTEGER PRIMARY KEY AUTOINCREMENT,
  page_id TEXT NOT NULL UNIQUE REFERENCES pages(id) ON DELETE CASCADE,
  user_id TEXT NOT NULL,
  expire_ts INTEGER NOT NULL
);
  • 坑：锁必须带过期时间。浏览器崩溃不会发解锁请求，没有 TTL 的锁会把文档永久锁死。

⑥ 冲突草稿

  • 用户操作：合并冲突后暂时离开，草稿和冲突块都保留，回来继续处理。
  • 实现：wiki_temp_draft 存 base_rev_no 与冲突内容（conflict_draft + conflict_json），按 (page_id, user_id) 唯一，带过期时间。
CREATE TABLE IF NOT EXISTS wiki_temp_draft (
  draft_id INTEGER PRIMARY KEY AUTOINCREMENT,
  page_id TEXT NOT NULL, user_id TEXT NOT NULL,
  base_rev_no INTEGER NOT NULL,
  conflict_draft BLOB NOT NULL, conflict_json BLOB NOT NULL,
  create_ts INTEGER NOT NULL, expire_ts INTEGER NOT NULL,
  UNIQUE(page_id, user_id)
);
CREATE INDEX IF NOT EXISTS idx_draft_expire ON wiki_temp_draft(expire_ts);
  • 坑：base_rev_no 必须一起存。只存冲突文本，下次打开时无法判断「线上又前进了几版」。

⑦ Yjs 实时协同

  • 用户操作：多人同时打开同一篇文档，光标与编辑实时同步。
  • 实现：服务端持有 Yjs 文档二进制状态 yjs_docs.ydoc_state，并用 base_rev_no 记录「这份快照对应哪个版本」。开房时先决定种子来源：信任快照、用版本链重建，或拒绝。
// src/collab/yjs-server.ts
export function decideRoomSeed(input: {
  storedBaseRevNo: number | null;
  snapshotText: string;
  hasSnapshot: boolean;
  latestRevNo: number;
  latestText: string | null;
}): RoomSeedDecision {
  if (input.latestText === null) return { action: 'refuse', baseRevNo: null, latestText: null };
  if (!input.hasSnapshot) {
    return { action: 'seed-from-chain', baseRevNo: input.latestRevNo, latestText: input.latestText };
  }
  const same =
    normalizeMarkdownContent(input.snapshotText) === normalizeMarkdownContent(input.latestText);
  // 旧行 base 可能为 null：靠正文比对兜底
  if (input.storedBaseRevNo === input.latestRevNo || same) {
    return { action: 'trust-snapshot', baseRevNo: input.latestRevNo, latestText: input.latestText };
  }
  return { action: 'replace-with-chain', baseRevNo: input.latestRevNo, latestText: input.latestText };
}
  • 坑：快照可能落后于版本链（进程崩在落盘之前）。所以开房必须先比对 base_rev_no 与最新版本号，再用正文归一化比对兜底，不能无条件信任 BLOB。
  • 面试点：collab_mode='normal' 的文档不给 editor 权限（return page.collabMode === 'normal' ? 'viewer' : 'editor'），避免 CRDT 与三路合并同时作用于同一篇文档。

权限体系

① 可见性模型

  • 用户操作：文档设为公开 / 私密 / 指定成员 / 团队可见；空间级另有「所有人可编辑」开关。
  • 实现：pages.visibility + page_allowed_users（页级白名单）+ space_allowed_users（空间级白名单）+ getAllowedPageTeams（团队可见）；allow_all_edit 控制编辑权限是否放开。
CREATE TABLE IF NOT EXISTS page_allowed_users (
  page_id TEXT NOT NULL REFERENCES pages(id) ON DELETE CASCADE,
  user_id TEXT NOT NULL REFERENCES users(id),
  PRIMARY KEY (page_id, user_id)
);
  • 坑：白名单表要建 (page_id, user_id) 复合主键。只建自增 ID 时，重复授权会插入多行，权限查询结果集膨胀。

② 权限计算与批量查询

  • 用户操作：目录、搜索、AI 问答都只返回「我可见」的内容。
  • 实现：getAllowedUserIdsByPage(pageIds) 一次查出多页的白名单，避免逐页查库；查询按 chunkIds 分批，绕过 SQLite 单语句变量上限。
// src/services/permission.ts
export function getAllowedUserIdsByPage(pageIds?: string[]): Map<string, string[]> {
  const map = new Map<string, string[]>();
  const rows = (pageIds
    ? chunkIds(pageIds).flatMap((ids) =>
        db.prepare(
          `SELECT page_id, user_id FROM page_allowed_users WHERE page_id IN (${ids.map(() => '?').join(',')})`
        ).all(...ids) as { page_id: string; user_id: string }[]
      )
    : db.prepare('SELECT page_id, user_id FROM page_allowed_users').all()) as { page_id: string; user_id: string }[];
  for (const r of rows) {
    const list = map.get(r.page_id) ?? [];
    list.push(r.user_id);
    map.set(r.page_id, list);
  }
  ...
}
  • 面试点：IN (...) 的占位符数量有上限（SQLite 默认 999），所以 chunkIds 分批。批量查询不比分批更慢，但会直接报错。

  ...

评论与批注

① 页面评论与回复

② 段评（批注）

  • 用户操作：选中一段文字 → 加批注 → 批注挂在选区上，正文改动后仍能定位。
  • 实现：page_annotations 存 quote（选中的原文）、prefix / suffix（前后文）、start_offset / end_offset（位置）、anchor_json（结构化锚点）。
// src/services/page-comments.ts
export function createAnnotation(input: AnnotationInput, publisherId: string, viewerId: string) {
  const id = `ann-${nanoid(10)}`;
  db.prepare(
    `INSERT INTO page_annotations
       (id, page_id, comment_id, user_id, quote, prefix, suffix, start_offset, end_offset, body, anchor_json, created_at, updated_at)

  ).run(id, input.pageId, input.commentId ?? null, input.userId, input.quote, input.prefix ?? '',

① 索引：切块入库

export async function indexPage(pageId: string, title: string, content: string): Promise<number> {

  const source = readCurrent();

      && current.content === source.content && current.latest_rev_no === source.latest_rev_no); };
  // Superseded snapshots must never remove newer chunks or serialize obsolete shared content.
  if (!isCurrent()) return 0;
  deletePageRagChunks(pageId);

}
