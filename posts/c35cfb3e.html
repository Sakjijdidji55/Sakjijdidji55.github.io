实现细节

  1. 账号与安全：Gin 中间件链 + JWT + bcrypt + Redis 验证码。验证码写 vcode:<email>、失败计数 vcode_fail:<email>（连错 5 次作废）；登录签发 access 7 天 / refresh 30 天，refresh 落 refresh_tokens 表；每次请求解析 JWT 拿到 userID 后先读 Redis 用户快照 user:session:<id>，把高频查库挡在中间件层。PAT 用 sk_xq_ 前缀区分，校验前置布隆过滤器，库里只存哈希。
  2. 帖子与浏览：Gin + GORM + Redis 两级缓存。列表按 searchsort（home/history/save/rating）组装 BrowseFilter，缓存键 post:browse:<feed> 带 generation 版本号 —— 发帖/删帖直接换 generation 整体失效，不用逐个删键；详情键 post:detail:<id> 由点赞、评论、投币、改隐私等所有写路径主动失效；浏览数 INCR 后打脏标记，5 秒批量回写 MySQL，Redis 不可用则降级直查。
  3. 评论与评分：一级评论 postPcomment、二级楼中楼 postCcomment 两张表，各自维护点赞/点踩/删除；列表缓存 comment:list:<postID>:<type>，写操作即失效；评论通知走异步 SMTP，不阻塞主事务。评分专区不复用评论表 —— 分类 → 评分贴 → 星级提交 → 评分评论是独立一套，避免多态字段污染。
  4. @ 提及：编辑期前端弹候选；提交期 parseMentionTokens 取 @ 后最多 4 个词逐级累积并追加「剥尾部标点」变体，批量调 resolveMentions 拿 name→userID，全局 Map 缓存只查缺失项；渲染期按昵称长度降序做最长前缀匹配 + 边界判定（空白/标点/CJK/HTML 标签），命中渲染链接、未命中灰色高亮。@小秋 是后端 goroutine 调内网 Agent，必须用 context.Background() 而非请求 ctx，否则响应返回就取消；拿回 Markdown 后以 bot 身份进程内回帖，双闸去重（trigger sync.Map + actor 60s 滑窗），私密帖静默跳过。@职位身份 用 staff alias 账号，候选按线程可用身份过滤。
  5. 投币系统：coin_throw 表加唯一索引（userID + targetType + targetID）兜住每人每内容 ≤2，CoinMaxPerTarget = 2 在 domain 层同步约束；一个事务内完成扣币 → 记投币 → 投币者 +10 经验/币 → 作者 0.1 分成/币 → 写流水。成功后失效 post:detail:<id> 与首页 Feed（里面带 coin_num）。cancel 以 coin_throw 行为凭证、不校验目标是否还在，撤回全部并退币退经验 —— 内容被删也该能退。
  6. 在线人数：Redis ZSET 双键滑动窗口，全站 presence:online、场景 presence:scene:<scene>:<id>，member=用户 ID、score=心跳毫秒。前端 60s 一次心跳、页面 hidden 暂停、回前台补报一次，PresenceBadge 只 setTarget 切场景、自己不起定时器。查询用单次 Pipeline 完成「清过期 + ZCARD」，窗口 150s；切场景时 ZRem 旧 key，并用 context.WithoutCancel 保证客户端断开后写事务不被取消。
  7. 工作台：9 个内置入口写死在前端，后端挂了也能点；动态应用来自 workbench_apps，GET /auth/workbench/apps 按名称去重后追加，targetType 只有 route（站内跳转）与 link（外链）两种。对外另有 SM2 验签中转接口，开发者平台的模块可远程建/查工作台应用而不碰主站库。
  8. 通知与私信：gorilla/websocket 建连（/websocket/auth/chat，token 允许走 query —— 原生 <audio>/EventSource 带不了 Header），clientMap 管在线连接。消息先落库再投递：对方在线且正处该会话则直推，否则未读 +1。未读键 {sender}RecvUnread{target}_{lane} 做计数，另维护索引集合 chatUnreadIndex:<uid>，让「哪些会话有未读」不用扫全库；进会话即清未读并删索引项。
  9. 内容板块：音乐/小说/视频同属 Gin + MySQL + 对象存储，媒体文件走 noauth 媒体路由（同样受 Header 限制所迫）。帖子内嵌音乐用独占行 ::music <id>::，渲染前替换成 <div data-music-id>，水合时批量拉 meta 变成可播卡片，播放交 Howler.js（支持 Range 流式拖动）。小说另有书/章两级结构、书评/章评/段评三类评论、书架收藏、阅读进度、积分签到（连胜 + 当日去重）。
  10. 社区与交易：商城/课程/需求是常规 CRUD + 对象存储；简历每人上限 5 份，预览走 30 分钟签名 URL（resumeDownloadURLTTL = 30 * time.Minute），文件流接口挂 OptionalAuth 让「登录 Bearer」与「签名链接」二者校验其一；抽奖创建时校验奖品与次数、参与用唯一约束防重复；反馈单表 + 状态标记。
  11. 个性化：勋章分注册周年 / 节日限定 / 特殊成就，定时任务 AwardDueAnniversaries 按注册周年自动发放；主页勋章墙最多 30 枚、批量查询上限 100 人、可单枚设「对外挂载」。皮肤是全站主题活动（有时间窗，游客也能读到当前主题），用户外观设置单独存；小秋独立成页，换肤靠前端主题变量驱动。
  12. 管理端：只接受 UniSSO 管理员登录（学院成员 + 白名单），管理员 JWT 单独 1 天有效期，与用户 token 物理隔离；成员管理、内容治理、推荐流灰度规则与重建、OAuth 应用、视频、博客发布、CDKey、数据看板统一挂 /admin 命名空间，写操作落审计与通知。

面试要点

  • 三套鉴权：用户 JWT(7d) / 管理员 JWT(1d) / OAuth2(5min)；另加 PAT（MCP 用）与布隆过滤器防刷。
  • 投币：coin/throw·cancel·summary·ledger·visit，每人每内容 ≤2，取消即退币；排行榜按投币数（ZSet）。
  • 在线：presence/heartbeat 30 次/分 + presence/stats 60 次/分，2.5min 窗口，Redis 存心跳。
  • @小秋：异步 goroutine（不能用请求 ctx）→ Agent → bot 身份回帖；双闸去重（trigger + actor 60s 滑窗），私密帖静默。
  • 推荐流：用户开关 + 阅读时长加权；管理端灰度规则可切。
  • 热度：赞+3/浏览+1/评论+6，删评论 0.5^days 衰减；精选走内部 /internal/featured。
  • 音乐内嵌 ::music id:: 占位符预处理 + 水合，Howler.js 流式支持 Range。

实现细节

  1. 容器：K3s 单节点 + 命名空间 clouds，一组一个 Ubuntu 24.04 Pod。groups.json 是权威组定义，groups.py 渲染 manifests/<group>.yaml（Deployment）后 kubectl apply；lifecycle.py 封装创建/启动/停止/重启/删除。Pod 状态、日志、资源占用、在线终端都是 kubectl 的 exec/logs 转 WebSocket。
  2. 部署：组内应用两种部署 —— 从 Git 仓库拉代码，或执行自定义 deploy.sh；进程由容器内 supervisord 托管，做到崩溃自启与开机自启。平台本体是 Flask + gunicorn，单 worker（SocketIO 需要粘性会话，多 worker 会串会话）。
  3. 网络与存储：Pod 只监听内网端口，公网经 frp（frpc → frps 中继机）隧道出去，中继机上的 nginx 按子域名反代到对应隧道端口。映射权威文件 proxy_mappings.json，一改就由 groups.py 重写 frpc 配置并同步 nginx 站点与证书。数据库/缓存/对象存储按桶和库粒度发凭证，拿到的是自己那一份。
  4. 监控与治理：fleet_sampler 每 15s 采本机与远程主机指标写 SQLite 时序；req_loop 用 EWMA 估算真实用量（new = α·observed + (1-α)·old）周期性回写 Pod 的 k8s requests，让调度器看到的配额贴近实测而不是拍脑袋；gpu_loop 盯 GPU 压力触发迁移/驱逐；告警走 PWA 推送。8 个守护进程全部 systemd 托管、统一读 .env。
  5. AI 与协作：agent.py 实现 ReAct —— 提示词 → 选工具 → 执行 → 观察 → 再决策，支持 fan-out 并行；工具由 mcp_client.py 注册的 MCP server 提供；知识库文件放 kb/，kb_service.py 入库 Qdrant，问答时双库召回。成员 owner/member + 4 角色权限，另发 API Token 供脚本调用。

面试要点

  • 每组一个 Pod，ns=clouds，frp 隧道 + 公网 nginx 暴露端口。
  • 8 个 systemd 守护：web/采样/EWMA 估算/GPU 调度/告警，全读 .env。
  • EWMA 调 k8s requests；GPU 压力迁移 + 优先级驱逐。
  • 配置与凭证分离，源码只有占位符。

实现细节

  1. 注册登录：Vue 3 + C++20（cpp-httplib，替换掉并发下会死锁的 vendored transport）+ MySQL 8 + Redis（ACL + 统一前缀）+ bcrypt + SMTP。登录支持密码 / 邮箱验证码 / 集市账号三种，会话写 Cookie，配登录限流与 CSRF 防护。
  2. 扫码与二次验证：二维码带一次性票据，手机上打开确认页，已登录即可一键批准 PC 登录；集市扫码走集市 OAuth 授权。二次验证在「无可信设备 Cookie」或「距上次登录超 7 天」时触发（step_up_days 默认 7），走邮箱验证码或动态人脸 —— 人脸只做二次验证、不作为登录凭证；验证通过只完成本次升级，不新建会话。
  3. 账号与 Claim：一个 UniSSO 账号可关联多个身份，双向显示、不分主次；授权同意时选本次用哪个账号，权限不合并。签发 claim 含 sub / sso_sub / sse_sub / preferred_username / name / picture / student_id / email / roles / internal；sso_sub 与 sse_sub 可能不同，接入方不能互相替换。
  4. 授权与应用：OAuth2 授权码 + PKCE(S256) + OIDC（discovery / JWKS / RS256）。/authorize → 登录或同意 → 回 code → code + code_verifier 换 access / refresh / id_token，refresh 轮换、旧的不再可用。对外应用由学院成员自助注册、提交即生效；内接应用由平台管理员建；应用管理页可直接下载接入 Skill。
  5. 设备与后台：会话表记设备信息，可查看、退指定设备、退其他所有设备。Redis 所有键统一加 REDIS_PREFIX 并用 ACL 限制权限，避免与其他服务撞键。组织只服务于应用管理 —— 超管建组织，组织管理员管本组织的开发者与应用；身份之外的角色、用户组、资源权限都归各应用自理。

面试要点

  • 授权码 + PKCE(S256)、OIDC discovery/JWKS、RS256。
  • claim：sub=sso_sub（UniSSO id），sse_sub（集市 id）可能不同，勿互替。
  • 二次验证不建会话，返回 step_up_required。
  • 边界：只管身份，应用内角色/用户组/资源权限归应用。

1. 账号与安全

技术栈：Go + Gin + GORM + MySQL 8 + Redis + JWT（golang-jwt）+ bcrypt + SMTP。

实现步骤

  1. 注册：邮箱验证码存 Redis（vcode:<email> + 失败计数 vcode_fail:<email>，连续失败 5 次作废），校验通过后 bcrypt 存密码。
  2. 登录：校验密码 → 签发 access（7 天）与 refresh（30 天），refresh 落 refresh_tokens 表。
  3. 鉴权：中间件取 Authorization: Bearer，解析 JWT 拿 userID，再取 Redis 用户快照 user:session:<id> 减少查库。
  4. 刷新：校验 JWT + 数据库记录「存在/未用/未过期」→ 旧记录置 is_used=true → 重新签发，一次性消费防重放。
  5. 三套并行：用户 JWT、管理员 JWT（1 天）、OAuth2 token（5 分钟，带 scope）；另有 PAT（sk_xq_）给 MCP。
  6. 限流：Redis 计数键 ratelimit:<scope>:<userID>:<窗口序号>，Redis 挂了 fail-open。

  4. 卸任负责人或年度复审不达标自动退出圆桌、释放席位。

关键代码

图

flowchart LR
  P["答辩通过"] --> Q{"有空位?"}
  Q -- 是 --> R["成为圆桌"]
  Q -- 否 --> W["候补队列"]
  W -->|按时间递补| R
  R -->|卸任/复审不达标| X["退出并释放"]

面试点

  • 候补必须按时间排序，不能按分数，避免反复插队。
  • 自动退出要触发递补，否则席位会空着。

5. 公示与内容

技术栈：公示生成器 + 打印样式 + FAQ/年鉴。

实现步骤

  1. 每次会议结果在 /teams 公示。
  2. 自动生成可打印/可复制的公示文档。
  3. 部门介绍、FAQ（分类/搜索/折叠）、年鉴与名人堂。
  4. 名人堂资料通过邮件邀请链接由本人填写。

关键代码

图

flowchart LR
  M["会议结果"] --> P["公示文档"]
  P --> T["/teams 列表"]
  P --> PP["打印/复制"]

面试点

  • 公示文档由系统生成而不是手写，保证数据一致。
  • 打印样式要单独写，否则截图式打印会丢格式。

6. 管理后台

技术栈：角色化标签页 + 部门/岗位/报名/答辩/圆桌管理。

实现步骤

  1. /admin 按角色显示标签：超管、部门管理员、资源方代表。
  2. 超管看全部用户；部门管理员只看本部门。
  3. 答辩标签对资源方代表只开放三级与被指派任务。
  4. 圆桌管理维护席位与负责人。

关键代码

图

flowchart LR
  R["角色"] --> A["超管: 全部"]
  R --> B["部门管理员: 本部门"]
  R --> C["资源方: 三级答辩"]

面试点

  • 后端必须再校验一次角色，不能只靠前端隐藏标签。

十、开发者平台

1. 登录与开发者申请

技术栈：集市 OAuth + JWT + 申请审批流。

实现步骤

  1. 集市 OAuth 登录，非开发者可提交申请。
  2. 管理员审批通过后标记为开发者。
  3. 开发者可改花名用于站内展示，留空恢复实名。

关键代码

图

flowchart LR
  U["登录"] --> C{"是开发者?"}
  C -- 否 --> A["提交申请"]
  A --> R["管理员审批"]
  R --> D["成为开发者"]
  C -- 是 --> D

面试点

  • 花名与实名分离，既保护隐私又不影响后台追责。

2. 模块注册

技术栈：模块表 + SM2 密钥对 + 密钥一次性下发。

实现步骤

  1. 开发者登记模块元信息（名称、slug、说明）。
  2. 注册时生成 SM2 密钥对。
  3. 平台只保存公钥，私钥在注册/轮换时一次性下发给模块方，平台不留存。
  4. 管理端可查看公钥、轮换密钥。

关键代码

图

flowchart LR
  M["模块注册"] --> G["生成 SM2 密钥对"]
  G --> S["平台存公钥"]
  G --> O["私钥一次性下发"]
  S --> V["后续验签"]

面试点

  • 平台不存私钥，泄露平台数据也伪造不了模块请求。
  • 一次性下发意味着丢了只能轮换，这是安全与可用性的取舍。

3. SM2 模块鉴权

技术栈：SM2withSM3 + 四段 token + 时间窗 + nonce 防重放。

实现步骤

  1. 请求头 x-model-Authorization：base64url(slug).base64url(ts).base64url(nonce).base64url(sign)。
  2. 另带 x-model-query-time（毫秒）。
  3. 签名串 slug\nts\nnonce\nqueryTime，用模块私钥签名。
  4. 服务端：ts 偏差 ±5 分钟；queryTime 偏差 ±60 秒且须与 ts 一致；SM2 验签。
  5. nonce 5 分钟内不可重复（防重放）。

关键代码

图

sequenceDiagram
  participant M as 模块
  participant D as 平台
  M->>M: sign = SM2(slug\nts\nnonce\nqueryTime)
  M->>D: x-model-Authorization + x-model-query-time
  D->>D: 解析四段 + 校验 ts/queryTime
  D->>D: 查 nonce 未用
  D->>D: 用公钥 SM2 验签
  alt 通过
    D-->>M: 数据
  else 失败
    D-->>M: 401
  end

面试点

  • queryTime 参与签名，是为了防止截获 token 后换个时间重放。
  • nonce 缓存只需 5 分钟，窗口与时间容差对齐即可。
  • 验签用 SM2withSM3，国密合规场景常见。

4. 权限与授权

技术栈：权限点 + 角色 + 直授 + 模块级 required_permission。

实现步骤

  1. 权限点分 developer.*（6 项）与 admin.*（9 项），可自定义。
  2. 内置 admin/developer 角色，可自建角色并勾选权限点。
  3. 用户可挂多角色；对单用户可 allow/deny，deny 优先。
  4. 模块/入口可配 required_permission，无权限列表不可见、详情 404。

关键代码

图

flowchart TB
  U["请求"] --> D{"直接 deny?"}
  D -- 是 --> X["拒绝"]
  D -- 否 --> A{"直接 allow / 角色权限?"}
  A -- 是 --> OK["放行"]
  A -- 否 --> X

面试点

  • deny 优先于 allow，才能做「临时封禁某个权限」。
  • 无权限返回 404 而不是 403，避免泄露资源存在性。

5. 管理台

技术栈：权限点细分到接口。

实现步骤

  1. 用户管理、开发者申请审批、平台入口增删改。
  2. 模块管理、文档外链、角色 CRUD、用户挂角色。
  3. 模块 API 授权审批（整组或单点 group.action）。
  4. 老数据 is_admin/is_developer 自动映射为内置角色。

关键代码

图

flowchart LR
  A["管理员"] --> U["用户/申请"]
  A --> M["模块/入口"]
  A --> P["角色/授权"]
  A --> G["模块 API 授权"]

面试点

  • 权限细分到接口，避免「有管理台权限就能调所有管理接口」。

十一、API 开放平台

1. 密钥与用量

技术栈：Express + JSON 存储 + 集市 OAuth + OpenAI 兼容网关。

实现步骤

  1. 用户 OAuth 登录，创建 API Key（可限域名）。
  2. 查看模型卡片、用量、余额流水。
  3. Key 只展示一次，库中存哈希/受控字段。

关键代码

图

flowchart LR

  C --> US["用量/余额流水"]

面试点

  • 定价按输入/输出分开，才能覆盖不同 token 成本。
  • 域名白名单防止 Key 被搬到其他站点滥用。

2. 调用与转发

技术栈：OpenAI 兼容接口 + vLLM 上游 + Bearer sk-。

实现步骤

  1. GET /v1/models 列出可用模型。
  2. POST /v1/chat/completions 带 Bearer sk-…。
  3. 网关按 Key 找模型配置，转发到对应 vLLM 上游。
  4. 支持流式；上游模型名用 served-model-name。

关键代码

图

sequenceDiagram

  participant V as vLLM

  G->>V: 转发

  G-->>C: 流式响应

面试点

  • 网关只做协议适配与治理，推理在 vLLM，职责清晰。
  • 流式要处理上游断连与客户端断开两种情况。

3. 计费与限流

技术栈：token 计数 + 余额扣减 + RPM/并发限制。

实现步骤

  1. 统计输入/输出 token 数。
  2. 按单价扣余额，写流水（含 balance_after）。
  3. RPM 与并发限制按 Key 维度。
  4. 余额不足直接拒绝。

关键代码

  B -- 是 --> D["扣费 + 写流水"]

面试点

  • 余额扣减要原子，否则并发调用会透支。
  • 流水记 balance_after，对账时能定位到具体一笔。

4. 管理配置

技术栈：管理台 + 模型注册。

实现步骤

  1. 注册模型：上游 Base URL、served-model-name、上游 Key。
  2. 配置入出单价、缓存价、图片价。
  3. 配置域名白名单、RPM、并发。
  4. 手动增减/设定用户余额。

关键代码

图

flowchart LR
  A["管理员"] --> M["注册模型"]
  M --> P["定价/限流/白名单"]
  P --> U["用户可用"]

面试点

  • 上游模型名与 served-model-name 不一致是最常见配置错误。

十二、TTS 与 AI 研究

1. TTS 语音合成

技术栈：GPT-SoVITS + 训练/合成任务队列 + 对象存储。

实现步骤

  1. 上传音频样本，训练音色（5 秒零样本 / 1 分钟少样本）。
  2. 选择音色与文本合成，生成音频。
  3. 运行记录可查看/试听/下载。
  4. 合成能力以 API 服务化，供其他平台调用。

关键代码

图

flowchart LR

  T --> V["音色库"]

  G --> O["音频输出"]

面试点

  • 训练与合成解耦，合成接口才能低延迟。
  • 样本质量直接决定克隆效果，要做前置校验。

2. 模型服务化

技术栈：vLLM + OpenAI 兼容 + supervisord + GPU Pod。

实现步骤

  1. 文本模型全部用 vLLM 承载（PagedAttention、连续批处理、前缀缓存）。
  2. 服务跑在 YatTerra 的 GPU Pod，supervisord 托管（崩溃自启/开机自启）。
  3. 统一 OpenAI 兼容 API，经 API 开放平台对外。
  4. 向量检索用 BGE-M3 召回 + reranker 精排。

关键代码

  • PagedAttention 解决 KV Cache 碎片，长上下文场景收益明显。
  • 前缀缓存对系统提示词复用场景提升很大。

3. 研究与评测

技术栈：压测脚本 + 指标采集 + 模型矩阵。

实现步骤

  1. 并发梯度、长上下文、工具调用三类实测。
  2. 记录吞吐、TTFT、成功率、前缀缓存命中率。
  3. 形成模型矩阵（多模态/轻量 LLM/视频/向量/TTS）。
  4. 研究 Agent 安全与人机协作新范式。

关键代码

  • 成功率与 TTFT 比单纯吞吐更能反映体验。
